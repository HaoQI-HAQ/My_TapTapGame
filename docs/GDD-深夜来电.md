## 1. 项目概述

### 1.1 基本信息

| 项目 | 内容 |
|------|------|
| 游戏名称 | 深夜来电 (Midnight Call) |
| 游戏类型 | 互动叙事 / 心理悬疑 / 解谜 |
| 目标平台 | 移动端（TapTap）、PC |
| 目标受众 | 18-30岁，喜爱悬疑叙事、手机模拟类游戏的玩家 |
| 游戏时长 | 单次通关 20-40 分钟，含多结局可反复游玩 |
| 开发周期 | 4-6 周 |
| 团队规模 | 1-3 人 |
| 引擎 | UrhoX (TapTap制造) |

### 1.2 一句话描述

**凌晨3点，手机里多了一个从未安装过的 app「回声」—— 里面记录着你已经遗忘的记忆。**

### 1.3 核心卖点

1. **元叙事体验** — 模拟真实手机界面，打破第四面墙
2. **递进式感知扭曲** — 随着深入，界面逐渐"失控"
3. **碎片化叙事** — 通过多个 app 中的线索拼凑完整故事
4. **多结局** — 玩家选择影响最终走向（3个结局）
5. **情感共鸣** — 关于遗忘、面对和释然的主题

## 2. 游戏世界观

### 2.1 背景故事

主角是一个普通上班族。三个月前经历了一件重大事件，但由于心理防御机制，这段记忆被完全封锁。

某天凌晨3点，一通无人应答的陌生来电将主角吵醒。挂断后发现手机中多了一个名为「回声」的 app。打开后，里面呈现的竟是主角自己被遗忘的记忆碎片——聊天记录、照片、录音、备忘录。

随着"回声"一层层解锁，真相逐渐浮出水面...

### 2.2 世界观设定

- 时间：当代现实世界
- 空间：完全在"手机界面"中展开
- 超自然元素：「回声」app 的来源不明确（可能是AI程序/可能是潜意识投射/可能是某人留下的）
- 基调：悬疑 → 压抑 → 温情/释然（或恐惧，取决于结局）

## 3. 核心玩法设计

### 3.1 玩法概述

玩家通过**操作模拟手机界面**，在多个 app 中翻阅信息、寻找线索、做出选择，逐步解锁被封锁的记忆。

### 3.2 手机模拟系统（Faux OS）

#### 主界面构成

```
┌──────────────────────────┐
│ 📶 信号  ⏰ 3:00 AM  🔋87% │  ← 状态栏（时间会随章节变化）
├──────────────────────────┤
│                          │
│  📞 电话    💬 消息      │
│                          │
│  📷 相册    📝 备忘录    │  ← 可交互的 App 图标
│                          │
│  🔊 回声    ⚙️ 设置      │
│                          │
│                          │
├──────────────────────────┤
│      [ 主页 ] [ 返回 ]   │  ← 导航栏
└──────────────────────────┘
```

#### 各 App 功能

| App | 功能 | 线索类型 |
|-----|------|---------|
| 电话 | 通话记录、来电事件 | 触发剧情推进 |
| 消息 | 聊天对话（类微信气泡） | 人物关系、事件细节 |
| 相册 | 照片浏览 | 视觉线索、时间线索 |
| 备忘录 | 文字笔记 | 主角心理状态、密码提示 |
| 回声 | 核心 app，记忆碎片播放 | 主线剧情推进 |
| 设置 | 隐藏信息入口 | 彩蛋/隐藏结局线索 |

### 3.3 章节系统（五次回声）

| 章节 | 标题 | 解锁条件 | 主题 |
|------|------|---------|------|
| 回声 1 | 陌生来电 | 游戏开始自动解锁 | 建立悬念 |
| 回声 2 | 被遗忘的人 | 在消息中找到关键对话 | 揭示重要人物 |
| 回声 3 | 那天晚上 | 相册中发现隐藏照片 | 事件核心 |
| 回声 4 | 碎裂的真相 | 备忘录密码解锁 | 真相冲击 |
| 回声 5 | 最终选择 | 完成前4章 | 结局分支 |

### 3.4 递进式扭曲系统

随着章节推进，手机界面逐渐"失控"：

| 阶段 | 视觉效果 | 交互变化 |
|------|---------|---------|
| 正常（回声1） | 界面清晰正常 | 正常操作 |
| 微异常（回声2） | 偶尔屏幕闪烁、通知抖动 | 某些按钮点击延迟 |
| 中度扭曲（回声3） | 文字偶尔乱码、颜色异常 | 时间显示跳变 |
| 严重扭曲（回声4） | 界面大面积 Glitch、重影 | 操作逻辑颠倒 |
| 崩溃/恢复（回声5） | 取决于结局走向 | — |

### 3.5 选择系统

关键节点提供选择，影响结局走向：

```
选择类型 A：信息获取类
  "要不要打开这条加密消息？"
  → 打开：获得更多线索
  → 不打开：错过信息，但避免某些心理冲击

选择类型 B：态度类
  "面对这段记忆，你选择..."
  → 面对：勇气+1
  → 逃避：封锁+1

选择类型 C：行为类
  "删除「回声」app？"
  → 删除：直接进入遗忘结局
  → 保留：继续深入
```

## 4. 叙事设计

### 4.1 角色设定

| 角色 | 身份 | 出现方式 |
|------|------|---------|
| 主角（玩家） | 上班族，记忆缺失 | 第一人称 |
| 小鹿 | 主角最好的朋友 | 聊天记录、照片 |
| 陌生来电者 | 身份未知 | 电话事件 |
| 回声 AI | app中的引导声音 | 文字提示 |

### 4.2 核心剧情线（剧透预警）

> 三个月前，主角与好友小鹿发生争执。当晚小鹿出了意外。
> 主角因为自责，心理防御机制封锁了所有相关记忆。
> 「回声」app 是小鹿在意外前设置的定时发送程序——
> 她预感到了什么，想留下最后的话。

### 4.3 三个结局

| 结局 | 条件 | 内容 |
|------|------|------|
| A. 释然 | 面对选择≥3 + 收集≥80%线索 | 接受真相，读完小鹿的最后留言，手机恢复正常。片尾：主角去了那个两人约定的地方 |
| B. 遗忘 | 中途删除app / 封锁选择≥3 | 记忆再次封锁，手机恢复正常，但主角永远不会知道真相。片尾：手机再次收到陌生来电... |
| C. 真相 | 收集全部隐藏线索 + 设置app彩蛋 | 发现「回声」app的真正创建者不是小鹿——而是未来的自己。时间循环暗示 |

## 5. 美术风格

### 5.1 整体风格

- **基调**：暗色系手机界面，模拟真实 OS
- **配色**：深灰/深蓝底 + 白色文字 + 紫色强调色（回声 app 主色）
- **特效**：Glitch 故障美学（扫描线、色彩偏移、噪点）

### 5.2 UI 设计参考

| 元素 | 风格 |
|------|------|
| 状态栏 | iOS/Android 混合风格 |
| App 图标 | 扁平化 + 微光影 |
| 聊天气泡 | 微信风格（绿色/白色） |
| 回声界面 | 暗紫色底 + 波形动画 + 粒子效果 |
| Glitch 效果 | RGB偏移 + 扫描线 + 随机闪烁 |

## 6. 音频设计

### 6.1 音效

| 场景 | 音效 |
|------|------|
| 来电 | 真实手机铃声（稍有失真） |
| 消息通知 | 清脆提示音 |
| 回声播放 | 低沉的嗡鸣 + 回响 |
| Glitch 发生 | 电流杂音/数字噪声 |
| 选择确认 | 轻按反馈音 |

### 6.2 背景音乐

| 阶段 | BGM 风格 |
|------|---------|
| 回声 1-2 | 安静环境音（夜晚、空调声） |
| 回声 3 | 低频合成器 + 心跳声 |
| 回声 4 | 失真钢琴 + 紧张节奏 |
| 回声 5（A结局） | 温暖钢琴独奏 |
| 回声 5（B结局） | 静默 + 遥远铃声 |
| 回声 5（C结局） | 诡异电子音 + 倒放人声 |

## 7. 技术方案

### 7.1 项目结构

```
scripts/
├── main.lua                 -- 入口，场景调度
├── PhoneOS/
│   ├── PhoneManager.lua     -- 手机系统管理（状态栏、导航）
│   ├── AppLauncher.lua      -- App启动/切换动画
│   └── NotificationSystem.lua -- 通知弹出系统
├── Apps/
│   ├── EchoApp.lua          -- 「回声」核心逻辑
│   ├── MessagesApp.lua      -- 聊天界面
│   ├── PhotosApp.lua        -- 相册
│   ├── CallLogApp.lua       -- 通话记录
│   ├── NotesApp.lua         -- 备忘录
│   └── SettingsApp.lua      -- 设置（隐藏线索）
├── Story/
│   ├── StoryManager.lua     -- 章节管理、状态追踪
│   ├── ChoiceSystem.lua     -- 选择与后果
│   ├── ClueTracker.lua      -- 线索收集进度
│   └── EndingResolver.lua   -- 结局判定
├── Effects/
│   ├── GlitchEffect.lua     -- 故障视觉效果
│   ├── ScreenShake.lua      -- 屏幕抖动
│   └── TextDistortion.lua   -- 文字扭曲
├── Data/
│   ├── chapters.lua         -- 章节数据配置
│   ├── dialogues.lua        -- 对话文本
│   ├── clues.lua            -- 线索定义
│   └── endings.lua          -- 结局条件
└── Utils/
    └── SaveManager.lua      -- 存档管理
```

### 7.2 技术要点

| 模块 | 技术方案 |
|------|---------|
| UI框架 | urhox-libs/UI（Flexbox布局） |
| 文字动画 | 逐字显示 + 打字机效果 |
| Glitch效果 | NanoVG 后处理（扫描线、色偏） |
| 数据驱动 | Lua table 配置所有对话/线索/分支 |
| 存档 | 本地 JSON 文件 |
| 音频 | 事件触发式播放 |

## 9. 风险评估

| 风险 | 等级 | 应对 |
|------|------|------|
| 文案质量不足导致叙事平淡 | 高 | 反复打磨，请外部玩家测试 |
| Glitch效果引发不适 | 中 | 提供"减少视觉效果"选项 |
| 手机模拟UI开发复杂度 | 中 | 简化为核心5个app，渐进开发 |
| 流程太短缺乏重玩价值 | 低 | 3结局+隐藏线索提供探索动力 |
